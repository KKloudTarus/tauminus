# ADR 0018: Mosh

- Status: accepted
- Date: 2026-10-23

## Context

Mosh keeps a terminal alive across sleep, a new network, and a changing
address, and shows typing at once on a slow link. Users who know it want
it in their terminal app. Its protocol (SSP over UDP, with AES-OCB and
terminal state sync) is large and subtle, and the roadmap asks for the
upstream `mosh-client` on macOS and Linux.

## Decisions

### Upstream's client, as the `mosh` script runs it

A third host protocol, Mosh, does what the `mosh` script does:

1. Sign in over SSH with the host's settings: user, port, keys, the vault
   identity, host key checks, and prompts all as for SSH.
2. Start the server with `mosh-server new -s -c 256`. The script looks
   for it in the `PATH` the login shell sets (Homebrew's, for one) and in
   the one sshd gave. It tries the host's own locale, then `C.UTF-8`, then
   `en_US.UTF-8`, since the server refuses to start without a UTF-8 locale.
3. Read `MOSH CONNECT <port> <key>` from its output. The line must stand
   alone, the port must be 1 to 65535, and the key must be 22 base64
   characters. Nothing else in the output is trusted.
4. Run the local `mosh-client` on a PTY with the address and port as
   arguments and the key in `MOSH_KEY`, the way upstream passes it. The
   address is the one the SSH connection reached, which `-s` made the
   server listen on; looking the name up again could answer with another
   machine (round-robin DNS, a first address that refused TCP). The SSH
   connection then ends.

The PTY session is an ordinary one to the app: output, resize, the prod
guard, history, broadcast, workspaces, and status dots all work as for
any pane. Mosh keeps its own session across networks, so the pane does
not reconnect it. Files, forwards, and key installs still go over SSH,
so a Mosh host keeps its Files button.

The client is looked for in `PATH` (absolute entries only, so a `.`
cannot name a file where the app was started), then in the places
package managers put it when a GUI app's `PATH` does not reach
(Homebrew on both chip families, MacPorts, Nix). Without one, the pane says to install Mosh.
The client needs a UTF-8 locale too; if the app's own is not one, the
client gets `C.UTF-8` (`en_US.UTF-8` on macOS).

### Limits stated, not worked around

- UDP goes straight to the host: a host behind a jump host or a proxy is
  refused rather than reached some other way.
- Windows is refused: upstream has no native Windows client.
- The host's character set does not apply; Mosh is UTF-8 only.
- A tmux setting does not apply; the shell Mosh starts is the login shell.

`hosts.json` becomes version 7 only when a Mosh host is saved.

## Consequences

- Mosh's security is upstream's: the key travels inside the SSH session,
  and the UDP traffic is encrypted with it. The key sits in the client's
  environment, readable by the user's own processes, as with `mosh`.
- A newer `mosh-client` reaches Tauminus through the user's package
  manager, with no release of ours.
